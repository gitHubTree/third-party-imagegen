# CPA / New API 接入（管理员）

可用链路：技能 → CPA，或技能 → New API → CPA。启用 CC-Switch 本机代理时保留该入口。本说明用于管理员配置，不要求普通使用者提供 CPA 上游密钥。

| 位置 | 要求 |
| --- | --- |
| Codex 当前供应商 | 兼容 API 基础地址，通常含 /v1；使用对应服务的用户 Key |
| New API 的 CPA 渠道 | 按部署要求配置 OpenAI 兼容渠道；常见配置为 CPA 服务根地址及 CPA API Key |
| 图片模型 | 添加部署实际支持的准确模型名；旧部署使用 gpt-image-2，不代表所有服务都支持 |
| 渠道与分组 | 渠道启用，用户令牌实际分组可访问此渠道，模型限制放行 |
| 额度与计费 | 确认账户余额、令牌额度和部署版本所需的模型计费配置 |

生成请求使用 `/v1/images/generations`，编辑使用 `/v1/images/edits`（以实际基础地址为准）。不要用聊天或 Responses 端点测试独立图片模型。

两类常见错误：

- `model_not_found` / `No available channel`：检查模型名、渠道启用状态、分组及模型限制。
- `only supported on ...images/generations...images/edits`：测试端点不正确，改用图片端点。

原文记录的 2026-10-19 案例中，真实图片请求曾因无可用渠道返回 503；后续后台测试又误用聊天端点。最终真实生成端点返回 200。这是不同问题，且服务端 200 不能证明本地保存、预览或编辑功能成功。

安装与本地检查无需真实出图。验证服务时使用用户已请求的图片任务，核对响应、保存文件和预览，不重复产生测试图片。
