# 故障排查

先运行 `--check`。它只检查本地配置、认证来源和 Pillow，不联网、不验证 Key 有效性、模型权限或额度。

| 现象 | 检查与处理 |
| --- | --- |
| Python 启动失败或缺少 tomllib | 使用 Python 3.11+ 创建虚拟环境 |
| 缺少 Pillow | 使用技能虚拟环境的 Python 安装 requirements.txt |
| 未找到当前供应商 | 检查 CC-Switch 是否已启用供应商及 CODEX_HOME 是否指向正确目录 |
| 尚未设置图片模型 | 确认供应商支持的图片模型，执行 `--set-model <模型名>` 保存；也可用 `--model` 只指定本次请求 |
| Key 不可用 | 检查供应商 env_key 对应环境变量能否被 Codex 进程读取；或检查当前供应商认证配置。脚本不读取 ChatGPT 登录令牌 |
| 400 | 检查图片模型和参数；省略不支持的可选参数需依据供应商说明，不能盲目反复出图 |
| 401/403 | 核对当前供应商认证和权限 |
| 404 | 核对 base_url 与图片路由。脚本在基础地址后追加 /images/generations 或 /images/edits，不自动补 /v1 |
| 429 | 检查余额、额度、并发及限流，不自动重试 |
| 503 | 核对服务状态；New API 检查图片模型、渠道启用状态和实际分组 |
| 连接失败 | 检查网络权限、CC-Switch 本机代理及上游服务；回环地址不一定有错，不绕过代理 |
| 超时 | 结果未知，先核对输出和服务日志，再决定是否重试 |
| 3xx | API 或下载地址发生重定向；脚本不跟随重定向，请服务提供方给出可直接访问的地址 |
| HTTP 200 但无图片 | 检查响应是否提供 data[0].b64_json 或可直接下载的 data[0].url，并检查输出路径权限 |
| 输出文件已存在 | 换新文件名，不覆盖 |

排查时仅使用脱敏日志、时间、状态码及请求 ID，不公开完整配置、Key、请求正文或原始错误响应。生成成功不代表编辑接口也可用。

脚本读取磁盘中的默认配置；若启动 Codex 时使用临时 `--profile` 或 `-c` 覆盖，需先核对脚本读取的供应商是否一致。不要自动改配置或尝试其他账号。

每次只处理一张图片；不支持遮罩、多输入图片或流式格式。供应商返回其他响应结构时需要适配，不能把聊天接口直接视为图片接口。
