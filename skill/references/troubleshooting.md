# 故障排查

先运行当前技能虚拟环境中的 `scripts/imagegen.py --check`。它显示供应商、入口类型（本机代理或远程服务）、认证来源和当前图片模型，不联网、不验证 Key 有效性、模型权限或额度。需要联网验证时运行 `scripts/imagegen.py discover`：请求不带提示词，不会生成图片。

错误提示只显示服务端返回的错误代码（如 `model_not_found`），不显示原始响应正文。

| 现象 | 检查与处理 |
| --- | --- |
| 提示需要 Python 3.11 | 用 3.11+ 的 Python 在仓库根目录重新运行 `install.py`，它会重建技能的 `.venv`；各系统获取方式见对应安装文档 |
| 技能目录没有 `.venv` | 未按安装脚本安装；在仓库根目录运行 `install.py` |
| 未安装 Pillow | 可选依赖，不影响生成和编辑。服务端返回格式与 `--out` 扩展名不同时按实际格式保存，以脚本输出的路径为准；需要严格按扩展名输出时运行 `install.py --with-pillow` |
| 未找到当前供应商 | 检查 CC-Switch 是否已启用供应商及 CODEX_HOME 是否指向正确目录 |
| 尚未设置图片模型 | 运行 `discover` 自动探测并保存；已知模型名时也可执行 `--set-model <模型名>`，或用 `--model` 指定本次请求（成功后自动记住） |
| 模型没有可用渠道（退出码 5） | 模型名与 New API 渠道不匹配，重试无效。脚本已清除该入口的旧记忆；运行 `discover`。全部候选都无渠道时，在 New API 为图片渠道添加准确模型名并放行分组 |
| 上游暂时不可用（退出码 6） | 上游过载或无可用账号，与模型配置无关；稍后经用户确认重试一次 |
| Key 不可用 | 检查供应商 env_key 对应环境变量能否被 Codex 进程读取；或检查当前供应商认证配置。脚本不读取 ChatGPT 登录令牌 |
| 其他未识别错误 | 提示中的括号内是异常类型名，据此排查；原始内容已隐藏 |
| 400 | 检查图片模型和参数；省略不支持的可选参数需依据供应商说明，不能盲目反复出图 |
| 401/403 | 核对当前供应商认证和权限 |
| 404 | 核对 base_url 与图片路由。脚本在基础地址后追加 /images/generations 或 /images/edits，不自动补 /v1 |
| 429 | 检查余额、额度、并发及限流，不自动重试 |
| 503 | 先看错误提示的分类：无可用渠道属于模型配置问题，过载属于暂时性问题；均未识别时核对服务日志 |
| 请求未发出（退出码 8） | 连接被拒绝：CC-Switch 本机代理或服务未运行；网络访问被拒绝：Codex 沙箱禁止联网，以联网权限重新运行同一命令。请求没有发出，重跑不会重复计费 |
| HTTPS 证书校验失败（退出码 8） | macOS 的 python.org 版 Python 需运行一次 `/Applications/Python 3.x/Install Certificates.command`；公司代理或自签名证书用环境变量 `SSL_CERT_FILE` 指定根证书。Homebrew、Windows、Linux 发行版的 Python 使用系统证书，通常无需处理 |
| WSL 中连接被拒绝 | Codex 在 WSL2 中运行而 CC-Switch 在 Windows 主机上时，WSL2 默认网络下 `127.0.0.1` 指向 WSL 自身。启用 WSL 镜像网络（`.wslconfig` 中设置 `networkingMode=mirrored`），或让 Codex 与 CC-Switch 运行在同一系统 |
| 提示词里的 `$`、引号或换行丢失 | shell 改写了参数。改用 `--prompt-file`，从 UTF-8 文本读取提示词 |
| 其他连接失败 | 检查网络、代理与上游服务。本机地址（如 CC-Switch 的 127.0.0.1）会自动绕过系统代理，远程地址沿用系统代理设置 |
| 无法写入模型记忆 | Codex 沙箱可能只允许写工作区。`discover` 和生成仍会成功，按提示在后续请求传 `--model`；或以可写权限运行一次 `discover` |
| 超时 | 脚本默认最多等待 600 秒。结果未知，先核对输出和服务日志，再决定是否重试；外层命令的超时不能短于脚本超时 |
| 3xx | API 请求不跟随重定向，以免把 Key 发往其他地址；核对 base_url。结果图片下载不带 Key，允许重定向 |
| HTTP 200 但无图片 | 检查响应是否提供 data[0].b64_json（可带 `data:image/...;base64,` 前缀）或可下载的 data[0].url，并检查输出路径权限 |
| 输出文件已存在 | 换新文件名，不覆盖 |
| 内置模型容量不足或不可用 | 自动读取当前 `third-party-imagegen` 技能并执行直接供应商 API；不要求额外官方 Key、不切换系统 CLI、不改用 PIL 等临时绘图 |

图片请求可能持续数十秒到数分钟。外层工具返回 `session_id` 时必须继续轮询原会话到最终退出码；中间输出不是失败，不能启动第二个生成进程。找不到已结束的进程也不是失败依据。

生成完成后检查文件存在且大小大于零，再用图片查看工具预览。Windows Markdown 图片和下载链接使用正斜杠，并指向同一个已检查文件；展示异常时修正路径或消息格式，不重新生成。

排查时仅使用脱敏日志、时间、状态码及请求 ID，不公开完整配置、Key、请求正文或原始错误响应。生成成功不代表编辑接口也可用。

脚本读取磁盘中的默认配置；若启动 Codex 时使用临时 `--profile` 或 `-c` 覆盖，需先核对脚本读取的供应商是否一致。不要自动改配置或尝试其他账号。

每次只处理一张图片；不支持遮罩、多输入图片或流式格式。供应商返回其他响应结构时需要适配，不能把聊天接口直接视为图片接口。
